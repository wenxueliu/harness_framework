# Harness Orchestration 用户旅程图

> 版本：v1.1  
> 状态：当前产品基线  
> 更新日期：2026-09-21  
> 关联文档：[产品需求文档](product-requirements.md)、[系统架构](architecture.md)、[Dashboard UI 设计](dashboard-ui-design.md)

## 1. 旅程目标

用户旅程围绕三个必须清楚分开的产品对象展开：

```text
作业流模板（可编辑、可发布）
        ↓ 发布产生不可变版本
作业流实例（绑定某个版本、拥有独立运行上下文）
        ↓ 启动产生运行记录
任务 / Task Attempt（具体执行、日志、证据和 Agent Session）
```

设计目标不是让用户记住内部组件，而是让用户在每个页面都能回答：

1. 我现在编辑的是模板草稿，还是正在运行的实例？
2. 这次实例使用的是哪个模板版本、哪组参数、哪个 Git 引用和哪个 Workspace？
3. 当前任务为什么能执行、为什么等待、失败后如何修复和重新执行？

## 2. 角色与权限

| 角色 | 主要目标 | 关键动作 |
|---|---|---|
| Owner | 管理项目组和执行边界 | 成员、Workspace、Execution Profile、归档 |
| Maintainer | 管理模板和运行 | 编辑、发布、创建实例、控制运行、变更重执行 |
| Developer | 编排和协作 | 编辑草稿、创建实例、查看日志、发送人工消息 |
| Viewer | 了解结果 | 查看模板、DAG、实例、日志和证据 |
| Platform / Agent | 完成自动执行 | 预检能力、启动 ACP Session、执行 Task、回传事件 |

权限以 Project Group 为边界。Project Group 不决定某个 Task 由哪个 Agent 执行；它只提供允许的执行策略和资源范围。

## 3. 端到端主旅程

```text
进入项目组
    ↓
创建/选择模板
    ↓
编辑 JSON + 实时 DAG 预览
    ↓
保存草稿 ───────────────┐
    ↓                   │
发布校验                │
    ↓                   │
仅发布 / 发布并创建实例 │
    ↓                   │
配置实例参数、Git、Workspace
    ↓
能力预检 ──失败──→ 修复能力 / 重新预检
    ↓通过
QUEUED → RUNNING → 查看 Task / Attempt / 证据
    ↓                         │
终态 ← 重试 Task              │
    │                         │
    └──修改并重新执行→ ChangeSet → successor instance
```

## 4. 旅程分段

### 4.1 进入项目组

| 用户动作 | 页面反馈 | 系统行为 | 失败与优化 |
|---|---|---|---|
| 选择 Project Group | 显示组名、角色、默认 Workspace 和可用策略 | 建立查询和权限上下文 | 无组权限时说明原因并提供只读入口 |
| 进入模板列表 | 展示草稿、已发布、归档和活跃实例数量 | 只返回当前组资源 | 归档组置为只读，禁止误操作 |
| 切换主题 | Light / Dark 即时切换 | 持久化用户偏好 | 状态不能只用颜色区分 |

### 4.2 创建和编辑模板

| 用户动作 | 需要看到什么 | 系统必须保证 |
|---|---|---|
| 创建模板 | 名称、描述、参数 Schema、空白节点定义 | 模板先处于草稿，不会立即执行 |
| 编辑 JSON | 格式化、Schema 提示、行号错误、节点定位 | JSON 是持久化输入，DAG 是规范化投影 |
| 查看 DAG | 节点、连线、根节点、叶节点、错误边 | 环、悬空依赖和重复 ID 在发布前被阻止 |
| 点击节点 | 节点详情、能力需求、完成门禁、风险提示 | 返回模板编辑页并保留 JSON/DAG 上下文 |
| 保存草稿 | 保存状态、revision、最近保存时间 | 不生成模板版本，不影响已发布版本 |

### 4.3 查看模板详情和发布

模板详情页是只读的产品解释页，不是编辑器。用户从列表进入详情后，应先理解当前版本，再决定编辑、发布或创建实例。

| 用户动作 | 页面反馈 | 结果 |
|---|---|---|
| 查看模板详情 | 名称、描述、版本、状态、只读 DAG、实例数量 | 确认将使用哪个版本 |
| 查看历史版本 | 版本状态、发布时间、DAG/参数差异 | 旧版本仍可被历史实例引用 |
| 点击发布 | 展示校验结果、风险项、版本号和变更摘要 | 校验通过才允许发布 |
| 保存为草稿 | 保留当前修订 | 不发布、不创建实例 |
| 仅发布 | 生成 Vn 不创建实例 | Vn 发布不影响 V1 实例 |
| 发布并创建实例 | 进入实例配置页 | 创建实例与发布动作可追溯、可重试 |

### 4.4 创建多个实例

一个模板版本可以创建多个实例。实例创建页必须主动说明“模板版本只读，以下配置仅属于本次实例”。

| 配置 | 实例级差异 | 固化时机 |
|---|---|---|
| 输入参数 | 每个实例可以不同，敏感值用 Secret Reference | 创建实例时校验并快照 |
| Git 分支 / Commit | 可以不同；最终解析为 commit SHA | 启动前或创建时按策略固化 |
| Workspace | 可以不同；必须在项目组允许范围内 | 启动前绑定 Run Workspace |
| Execution Profile | 可以从允许列表选择或继承默认 | Attempt 预检时解析 |
| Skill / MCP | 按 Task 需求和项目组策略装配 | Attempt 生成 Manifest 时固化 |

用户可选择“稍后启动”或“立即执行”。稍后启动只创建实例，不应误显示为失败；立即执行则进入能力预检。

### 4.5 执行与观察

实例详情页是一次执行事实的主入口，顶部始终展示模板、版本、实例 ID、Run、Git、Workspace 和状态。

```text
实例详情
├── 上下文摘要：版本 / 参数摘要 / Git / Workspace
├── 能力状态：Preflight / Manifest / Agent Runtime / Skill / MCP
├── DAG 运行投影：Task 状态和依赖阻塞
├── Task 详情：Attempt / Session / 日志 / 证据 / 产物
└── 控制动作：暂停 / 恢复 / 中止 / Task 重试 / 修改并重执行
```

执行前：

1. 系统展示能力预检进度和阻塞原因；
2. 缺少 Agent Runtime、Skill、MCP、Workspace 或权限时进入 `WAITING_FOR_CAPABILITY`；
3. 用户可跳转到修复建议，修复后重新预检；
4. 通过后保存 Execution Manifest，再进入队列。

执行中：

1. 用户点击 DAG 节点进入节点详情；
2. 节点详情展示当前 Attempt、ACP Session、工具调用、日志、证据和 Workspace；
3. 用户可发送人工消息、暂停、恢复、重试或中止，但危险操作需要确认；
4. 节点详情提供“返回实例详情”和“返回模板详情/编辑页”的来源感知路径。

执行后：

1. 终态实例保留所有 Attempt、Manifest、事件和审计记录；
2. Task 重试创建新 Attempt，不覆盖旧日志；
3. 实例删除按状态限制，并明确删除范围；
4. 结果可以跳转到证据、产物和失败修复建议。

### 4.6 从运行实例修改并重新执行

用户在实例详情点击“修改并重新执行”后，系统先区分变更范围：

```text
实例级变更：只影响本次执行 → Instance ChangeSet → successor instance
模板级变更：影响后续使用 → 新模板草稿 → 发布 V(n+1) → 新实例
```

交互步骤：

1. 选择修改参数、Git、Workspace、Task 定义或依赖；
2. 系统显示直接变更、间接受影响节点和必须重跑节点；
3. 系统说明哪些产物可以复用，以及复用的校验依据；
4. 用户确认后创建 successor instance；
5. 原实例进入保留/排空/终态流程，不被原地覆盖；
6. successor 获得新的 Attempt Manifest，并保留来源实例和 ChangeSet 链接。

### 4.7 删除与数据保留

| 对象 | 可删除条件 | 页面文案 |
|---|---|---|
| 无实例模板 | 从未绑定实例 | “删除模板及其草稿定义” |
| 有实例模板 | 不允许物理删除，只能归档 | “归档后保留历史实例” |
| QUEUED 实例 | 可以删除，取消尚未开始的执行 | “删除排队实例，不会启动任务” |
| 终态实例 | 可以删除，清理实例级数据 | 展示日志/产物保留策略 |
| RUNNING / PAUSED / DRAINING | 不可直接删除 | 先中止或等待安全终态 |

删除前显示对象、影响范围、关联版本和不可恢复数据；服务端再次校验权限和状态并记录审计。

## 5. 状态与页面映射

| 领域状态 | 用户看到的含义 | 可用主操作 |
|---|---|---|
| `DRAFT` | 模板草稿，尚未形成可执行版本 | 编辑、校验、发布、删除 |
| `PUBLISHED` | 不可变模板版本 | 创建实例、查看、归档/禁用 |
| `WAITING_FOR_CAPABILITY` | 执行条件未满足 | 查看阻塞项、修复、重新预检 |
| `QUEUED` | 条件满足，等待资源或调度 | 查看、删除、取消启动 |
| `RUNNING` | 至少有 Task 正在执行 | 观察、暂停、中止、Task 操作 |
| `PAUSED` | 新工作暂缓，历史保留 | 恢复、中止、查看 |
| `DRAINING` | 不再激活新工作，等待安全边界 | 等待、强制中止 |
| `SUCCEEDED` / `FAILED` | 本轮执行已结束 | 查看、Task 重试、修改重执行、删除 |
| `SUPERSEDED` | 已由 successor 继续执行 | 查看 successor、历史审计 |

## 6. 页面导航图

```text
/templates
├── /templates/new
├── /templates/:templateId
│   ├── /versions/:versionId
│   └── /edit
└── /templates/:templateId/instances/new

/instances
└── /instances/:instanceId
    ├── /tasks/:taskId
    ├── /attempts/:attemptId
    ├── /preflight
    ├── /manifest
    └── /changesets/:changesetId
```

任何节点详情都必须保存来源上下文：从模板编辑页进入时返回编辑页，从模板详情页进入时返回详情页，从实例 DAG 进入时返回实例详情页；缺少来源时默认返回实例详情页。

## 7. 当前体验优化优先级

### P0：用户无法完成闭环

- 模板详情与编辑页混在一起，用户无法确认“查看”还是“修改”；
- JSON、DAG、版本和实例的边界不够明显；
- 新作业流模型尚未完全接入 ACP 执行链路；
- 能力缺失没有独立状态，用户无法知道为什么任务没有启动；
- 节点详情返回路径不稳定；
- 发布、创建实例和立即执行的动作边界容易混淆。

### P1：可以完成但成本较高

- 版本 Diff、参数表单、Git/Workspace 校验和实例上下文摘要不足；
- Task Attempt、Agent Session、MCP 调用和 Skill 来源分散在日志中；
- 失败后缺少可执行的修复建议；
- Light / Dark 主题下的 DAG、状态徽标和编辑器需要统一设计令牌；
- API 与 UI 自动化用例没有覆盖完整用户旅程。

### P2：规模化后再优化

- 批量创建实例和实例模板化配置；
- 资源队列、预算使用和能力健康度看板；
- 多人草稿协作、模板 Diff 和审批流；
- 大模型编排提案与人工确认；
- 定时、Webhook 和外部事件触发。

## 8. 旅程验收标准

1. 用户从模板列表进入详情，再进入编辑，不会误修改已发布版本。
2. 用户能在同一页面理解 JSON 与 DAG 的对应关系，并定位校验错误。
3. 用户可以保存草稿、仅发布或发布并创建实例，三种动作结果明确。
4. 同一模板版本创建的多个实例可以拥有不同参数、Git、Workspace 和能力配置。
5. 实例启动前能看到能力预检和 Execution Manifest；缺失能力不会静默失败。
6. 用户点击任意 DAG 节点后可以返回原上下文。
7. 运行实例修改后产生 successor instance，旧实例仍可审计。
8. QUEUED 和终态实例可以按规则删除，运行中实例不会被误删。
9. Light / Dark 模式下文本、DAG、状态、告警和编辑器均可读。
10. API、UI 自动化和关键状态转换覆盖上述主旅程。
