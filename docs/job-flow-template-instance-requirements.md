# 作业流模板与作业流实例需求文档

版本：v1.1  
状态：已确认，进入技术设计与实现拆分
更新日期：2026-09-21

## 1. 产品定位

本项目是一个多 Agent 作业流编排与执行平台。

用户通过人工方式创建可复用的作业流模板，定义任务节点、依赖关系、执行 Agent 和完成条件。模板发布后，可以创建多个相互隔离的作业流实例。每个实例独立执行、记录状态、保存日志，并支持暂停、恢复、重试、人工介入和变更重执行。

核心链路：

```text
人工创建模板 → 编辑 DAG → 保存草稿 → 校验
  → 发布模板版本 → 创建作业流实例
  → Agent 按依赖执行任务 → 监控、干预、重试或变更重执行
```

## 2. 本期范围

### 2.1 本期包含

- 作业流模板的创建、编辑、保存、删除和归档；
- 手工创建 DAG、编辑节点和依赖；
- 模板版本管理；
- 一个模板创建多个实例；
- 多实例并行执行；
- 实例输入参数、Git 分支和 Workspace 隔离；
- 节点执行、Attempt、Session 和日志记录；
- 暂停、恢复、中止、重试和人工消息；
- 从运行实例创建变更集并重新执行；
- 受影响节点分析和可复用产物判断；
- 模板和实例的权限、审批和审计；
- 节点详情页返回原实例或模板编辑上下文；
- Light / Dark 主题切换。
- Task Capability Requirements、Execution Profile、Skill Bundle、MCP Grant、Agent Runtime 和 Attempt Execution Manifest 的执行前预检与审计。

### 2.2 本期不包含

- 大模型自动生成 DAG；
- 大模型对话式修改作业流；
- AI 计划提案和 AI Diff；
- `dev → staging → production` 环境晋级；
- 固定的三环境模型；
- 通用项目管理、工时和绩效管理；
- 替代 Git、CI/CD、日志或制品系统。

后续如果增加大模型编排，应作为独立规划能力接入，不能绕过人工确认直接修改或发布模板。

## 3. 领域对象与术语

### 3.1 作业流模板 Workflow Template

可复用的作业定义，拥有稳定身份，但自身不执行任务。

模板包含：

- 名称和描述；
- 所属 Project Group；
- 节点定义和 DAG 依赖；
- Agent 配置；
- 节点完成条件；
- 实例参数 Schema；
- 默认 Workspace 或 Workspace 约束；
- 并发上限；
- 版本和归档状态。

项目归属规则：

- 当前系统没有独立的 Project 对象，模板归属于 Project Group；
- 每个模板只能有一个主 Project Group，模板列表、编辑、发布和删除都必须在该项目组权限范围内；
- 实例不单独选择项目组，实例通过 `template_id` 继承模板的 Project Group；
- 实例的参数、Git 分支、Workspace 和执行策略可以不同，但不能改变项目组归属；
- 项目组归档后不能创建或修改新的模板/实例，历史模板版本和实例仍可查询。

模板删除规则：

- 从未绑定任何作业流实例的模板允许物理删除，删除其草稿、版本索引和已发布版本；
- 只要模板曾经绑定过实例（包括已完成、失败、归档或被后继实例替代的实例），就不允许物理删除；
- 已绑定实例的模板只能归档，归档不影响已有实例和实例历史。

### 3.2 模板版本 Template Version

模板发布后形成不可变快照，例如 v1、v2、v3。

规则：

- 已发布版本不能原地修改；
- 新修改必须基于已发布版本创建新草稿；
- 新草稿发布后形成新版本；
- 新版本不影响旧版本和旧实例；
- 历史版本可以继续查看；
- 被禁用或归档的版本不能创建新实例；
- 已有实例继续使用创建时绑定的版本。

版本生命周期：

```text
DRAFT → PUBLISHED → DISABLED → ARCHIVED
```

### 3.3 作业流实例 Workflow Instance

某个已发布模板版本的一次具体使用。

实例拥有独立的：

- 模板版本引用；
- 输入参数快照；
- Git 分支或 Commit；
- Workspace；
- Task 状态；
- Task Attempt；
- Agent Session；
- 日志、证据、产物和审计记录。

同一个模板版本允许创建多个实例，并允许并行执行。一个实例创建后不能切换到另一个模板版本。

### 3.4 Project Group

Project Group 是当前产品的项目边界、权限边界和资源边界，不是 DAG、模板版本或实例。

```text
Project Group
  └── Workflow Template
        └── Template Version
              └── Workflow Instance
```

当前不引入 `Project` 作为 Project Group 和模板之间的额外层级。

### 3.5 Run

Run 是作业流实例的执行记录。用户界面优先使用“作业流实例”，运行详情中展示 Run ID 作为技术标识。

### 3.6 Task 与 Task Attempt

- Task：模板版本中的逻辑任务节点；
- Task Attempt：某个实例中该 Task 的一次有围栏执行；
- 节点重试创建新的 Attempt，但仍属于同一个实例；
- 整个实例重新执行创建 successor instance，不复用原实例身份。

### 3.7 Service Name

可选的任务归属信息，表示任务影响的业务服务或代码边界。

`service_name`：

- 不是实例必填参数；
- 不决定由哪个 Agent 执行；
- 不决定 Workspace；
- 可用于筛选、影响分析和任务展示。

### 3.8 执行能力对象

- Task 只声明抽象能力需求，不直接绑定一个长期运行的 Agent 进程；
- Execution Profile 约束运行时、Workspace、资源、网络和 Secret 策略；
- Skill Bundle 是版本化的 Agent 指令和辅助资源；
- MCP Server 是外部工具/数据服务，MCP Grant 决定本次 Attempt 是否可以暴露和调用；
- Agent Runtime/Adapter 负责通过 ACP 启动具体 Agent，并声明 Skill/MCP 注入能力；
- Capability Preflight 在 Attempt 启动前检查上述对象；
- 通过后生成不可变 Execution Manifest，失败时进入 `WAITING_FOR_CAPABILITY` 或 `UNROUTABLE`；
- stage-bridge 不属于本产品的执行或兼容路径。

## 4. 模板创建与发布

### 4.1 创建模板

用户可以：

1. 创建空白模板；
2. 基于已有模板或版本复制新模板；
3. 手动新增、编辑、复制和删除 Task；
4. 调整 Task 之间的依赖；
5. 配置 Agent、完成条件和可选的 Service Name；
6. 保存为草稿。

本期不提供 AI 生成或 AI 修改入口。

### 4.2 草稿规则

- 新模板创建后立即进入草稿状态；
- 模板草稿支持自动保存；
- 同一个模板同一时间只允许一个当前草稿；
- 保存草稿不会发布，也不会创建实例或执行任务；
- 草稿离开页面后可以恢复；
- 草稿编辑支持撤销和重做；
- 未发布且没有实例的模板可以删除；已发布但仍没有实例的模板也可以删除；
- 只要模板存在绑定实例，就不能删除，只能归档。

### 4.3 发布校验

发布前必须执行服务端校验，至少包括：

- Task ID 唯一；
- Task 名称和描述完整；
- 依赖节点存在；
- 不存在自依赖；
- DAG 不成环；
- Agent 配置有效；
- 完成条件完整；
- 实例参数引用有效；
- 外部副作用节点声明幂等或补偿策略。

校验错误必须定位到具体节点或边。校验失败时禁止发布。

### 4.4 发布动作

发布确认层提供三个动作：

- 保存为草稿：保存后继续编辑，不发布；
- 仅发布：生成模板版本，不创建实例，不执行任务；
- 发布并创建实例：生成模板版本，同时进入实例创建流程。

发布动作需要：

- 发布权限；
- 显式确认；
- 发布摘要；
- 版本号；
- 操作者、时间和审计记录。

## 5. 实例创建

### 5.1 实例创建规则

- 默认使用模板最新可用版本；
- 允许用户选择历史可用版本；
- 实例创建后固定绑定版本；
- 实例创建需要实例创建权限；
- 多个实例可以同时运行；
- 超过模板并发上限的实例进入排队状态；
- 实例创建请求必须支持幂等。

### 5.2 实例参数

模板定义参数 Schema，包含：

- 参数名称；
- 类型；
- 是否必填；
- 默认值；
- 可选值；
- 描述；
- 是否为敏感参数。

实例保存实际参数快照。模板后续变化不影响已经创建的实例。

敏感参数只能保存 Secret Reference，不能把明文写入模板、实例历史、Agent Prompt 或日志。

### 5.3 Git 与 Workspace

Git 分支、Commit 和 Workspace 属于实例执行上下文：

- 模板可以定义默认值或允许范围；
- 实例创建时选择实际值；
- 实例启动后执行上下文冻结；
- 运行中的实例不能直接切换 Workspace 或 Git 版本；
- 需要变更时创建 successor instance。

本期不引入 Environment 作为必填执行上下文，也不设计环境晋级流程。

## 6. 实例生命周期

实例生命周期独立于 Task 生命周期：

```text
QUEUED → RUNNING → DRAINING → SUCCEEDED
                    ├────────→ FAILED
                    ├────────→ ABORTED
                    └────────→ SUPERSEDED

RUNNING ⇄ PAUSED
```

补充规则：

- `QUEUED`：等待并发资源；
- `RUNNING`：允许调度和执行任务；
- `PAUSED`：暂停调度新任务；
- `DRAINING`：不再激活新任务，等待当前任务到达安全边界；
- `SUPERSEDED`：被 successor instance 替代；
- 尚未开始执行的 `QUEUED` 实例可以删除；
- `RUNNING`、`PAUSED` 和 `DRAINING` 实例不能删除，必须先中止或等待进入终态；
- `SUCCEEDED`、`FAILED`、`ABORTED`、`SUPERSEDED` 和 `ARCHIVED` 状态的实例允许物理删除；
- 删除实例会删除实例任务、日志、执行记录和事件等实例数据，不影响模板、模板版本或其他实例；
- 删除前前端必须二次确认，服务端必须再次校验实例状态和操作权限。

## 7. 运行实例的修改与重新执行

### 7.1 两种变更模式

#### 实例级变更

只影响当前实例，不改变模板和模板版本。

```text
实例 A / v1
  → Instance ChangeSet
  → successor instance A-2 / v1
```

#### 模板级变更

影响未来实例，并可选择创建 successor instance 执行新版本。

```text
模板 v1
  → 新草稿
  → 发布 v2
  → successor instance / v2
```

### 7.2 变更流程

1. 用户从实例详情发起“修改并重新执行”；
2. 选择“仅修改本次实例”或“修改模板”；
3. 编辑节点、依赖、参数或执行配置；
4. 系统分析直接变更和间接受影响节点；
5. 用户确认变更范围和复用范围；
6. 服务端校验变更后的 DAG；
7. 先创建并准备 successor instance；
8. successor 创建成功后，旧实例进入 `DRAINING`；
9. 旧实例停止后，successor 开始执行；
10. 保存旧实例与 successor 的关系和审计信息。

如果 successor 创建失败，旧实例继续运行，不能因为新实例失败而丢失原执行。

旧实例也可以由用户选择“立即中止”，但必须二次确认并填写原因。

### 7.3 重试和重跑的区别

- Task 失败：创建新的 Task Attempt，仍属于原实例；
- 整个实例重跑：创建 successor instance；
- 修改模板后重跑：发布新版本，再创建 successor instance；
- 旧实例历史默认不删除、不覆盖；用户明确删除终态实例时，按实例删除规则清理该实例数据。

### 7.4 产物复用

只有满足以下条件，旧产物才允许复用：

- Task 定义未变化；
- 上游依赖未变化；
- 实例参数兼容；
- Git 和 Workspace 兼容；
- 执行策略兼容；
- 产物仍在有效期内；
- 没有新的外部副作用要求。

系统需要展示：

- 直接变更节点；
- 必须重跑节点；
- 可以复用节点；
- 复用依据。

不能仅凭 Task 名称相同就复用产物。

## 8. 外部副作用与安全

涉及部署、发送消息、修改数据库或其他外部系统的 Task，必须具备：

- 幂等键；或
- 明确的补偿操作；或
- 人工确认门禁。

实例 ID、Task ID、Attempt ID 和业务幂等键共同用于避免重试、并行实例或版本变更造成重复副作用。

## 9. 权限与审批

至少区分以下权限：

- 查看模板；
- 编辑模板草稿；
- 发布模板版本；
- 创建实例；
- 控制实例；
- 修改并重新执行；
- 禁用模板版本；
- 管理 Workspace。

以下操作需要显式确认并审计：

- 发布模板版本；
- 发布并创建实例；
- 中止实例；
- 删除终态实例；
- 从实例修改并重新执行；
- 禁用模板版本；
- 执行具有外部副作用的 Task。

## 10. 页面与用户旅程

### 10.0 项目组上下文

1. 用户先进入一个 Project Group 上下文；模板列表和实例列表按该项目组过滤。
2. 创建模板时必须绑定当前 Project Group，模板详情显示所属项目组。
3. 模板发布和创建实例继续使用同一个项目组权限边界。
4. 创建实例时只选择模板版本、参数、Git 和 Workspace；项目组从模板继承并只读展示。
5. 如果用户没有指定项目组上下文，受保护模式下系统拒绝列出模板或实例，避免跨项目组泄露数据。

### 10.1 模板列表

展示模板名称、当前发布版本、草稿状态、最近更新时间、可用版本数、活跃实例数和所属 Project Group。

### 10.2 模板详情页

模板详情页是发布版本的只读查看页，展示：

- 模板名称、描述、所属 Project Group、状态和更新时间；
- 当前发布版本及历史版本入口；
- 当前版本的只读 DAG；
- 节点数量、根/叶节点、校验结果和风险提示；
- 活跃实例数、历史实例入口和创建实例入口；
- 编辑草稿、复制模板、归档或删除等有权限的操作。

JSON 是模板定义的输入和持久化表达，DAG 是服务端规范化定义的可视化投影，不是第二份独立数据源。详情页默认只读，不能直接修改已发布版本。

### 10.3 模板编辑页

采用三栏结构：

- 左栏：模板名称、描述、参数 Schema 和编辑历史；
- 中栏：JSON 定义与 DAG 实时预览；
- 右栏：Task 详情、节点/边校验信息。

顶部展示草稿保存状态、当前草稿版本、撤销 / 重做、校验、保存草稿和进入发布。JSON 变更后，DAG 预览必须同步刷新；错误应定位到具体节点、边或 JSON 字段。

### 10.4 实例创建页

展示并确认模板名称和版本、实例参数、Git Branch / Commit、Workspace、并发和资源提示。

### 10.5 实例详情页

展示模板名称和版本、实例 ID、Run ID、输入参数快照、Git 和 Workspace、实例状态、DAG 进度、Task Attempt、Agent Session、日志、证据、产物，以及暂停、恢复、中止、重试和修改并重新执行入口。

点击节点进入节点详情页后，必须显示明确的“返回”入口，并返回原来的模板编辑页或实例详情页，不能只依赖浏览器后退。

### 10.6 Light / Dark

- 首次访问默认跟随系统主题；
- 用户可以手动切换 Light / Dark；
- 用户选择需要持久化；
- 所有页面共用主题变量；
- DAG、状态颜色、弹窗、编辑器和节点详情同步切换。

## 11. 非功能要求

- 草稿保存必须具备版本号和并发控制；
- 发布、实例创建和变更重执行必须支持幂等；
- 所有写操作记录 actor、时间、请求 ID 和审计事件；
- 模板版本和实例执行上下文不可被静默覆盖；
- 多实例运行时 Task 状态必须按实例隔离；
- 外部副作用必须具备幂等或补偿机制；
- 核心页面支持刷新和恢复；
- 状态不能只通过颜色表达；
- 节点详情和实例详情支持键盘返回和可访问性操作。

## 12. MVP 验收标准

1. 用户可以手动创建一个空白作业流模板。
2. 用户可以新增、编辑、删除 Task 和依赖。
3. 成环、悬空依赖和缺失必填字段会阻止发布。
4. 用户可以保存草稿，刷新或离开后可以恢复。
5. 用户可以发布 v1，且发布不会修改草稿历史。
6. 用户可以基于同一模板创建多个实例。
7. 多个实例的 Task 状态、日志和 Workspace 互不污染。
8. 发布 v2 后，已有 v1 实例不受影响。
9. 用户可以从运行实例创建实例级变更，并重新执行。
10. 用户可以创建模板级 v2，并使用 v2 创建新实例。
11. 节点失败重试产生新的 Attempt，不覆盖历史 Attempt。
12. 整实例重跑产生 successor instance，并保留旧实例关系。
13. 模板详情页可以只读展示当前版本的 JSON 摘要、DAG、校验结果和实例入口。
14. 模板编辑页可以编辑 JSON，并同步展示 DAG 预览和节点/边级错误。
15. 系统能展示直接变更、必须重跑和可复用节点。
16. 排队中和终态实例可以删除，运行中的实例不能删除。
17. Attempt 启动前有能力预检和 Execution Manifest；未授权 MCP 不会进入 Agent Session，Skill 注入不兼容时不会静默启动。
17. 高风险操作需要确认并生成审计记录。
18. 点击节点进入节点详情页后，可以返回原模板详情、模板编辑或实例页面。
19. Light / Dark 模式可以切换并在刷新后保持。
